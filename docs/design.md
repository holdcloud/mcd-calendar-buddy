# 设计说明 — 麦麦日历助手

## 1. 产品定位

把麦当劳 MCP「活动日历查询」返回的活动信息，转换为 macOS 系统日历事件，让用户在常用日历里被动收到麦当劳活动提醒。

核心一句话：**"帮我盯着麦麦的活动，到点提醒我。"**

## 2. 架构

```
┌─────────────┐     ┌──────────────┐     ┌───────────────┐     ┌──────────────┐
│  入口层      │     │  MCP 数据层   │     │  转换层        │     │  同步层       │
│  cli.py     │ ──► │  mcd_client  │ ──► │  event_builder│ ──► │ calendar_sync│
│  (自然语言   │     │  (mcd-mcp    │     │  (活动→VEVENT) │     │ (macOS 日历)  │
│   /CLI)     │     │   Server)    │     │               │     │              │
└─────────────┘     └──────────────┘     └───────────────┘     └──────────────┘
```

### 模块职责

| 模块 | 职责 |
| --- | --- |
| `src/cli.py` | 命令行入口与参数解析：`sync --days N --remind 1d` 等 |
| `src/mcd_client.py` | 封装麦当劳 MCP 调用：连接管理、活动日历查询 Tool 调用、错误重试 |
| `src/event_builder.py` | 数据转换：活动 JSON → iCalendar VEVENT（标题、起止时间、描述、VALARM 提醒）；字段缺失时的降级策略 |
| `src/calendar_sync.py` | macOS 日历写入：优先 AppleScript（osascript）操作 Calendar.app；提供 `.ics` 文件导出兜底；基于活动 ID 去重 |

## 3. 关键设计决策

### 3.1 写入 macOS 日历的方案

- **方案 A（主选）：AppleScript**。通过 `osascript` 向 Calendar.app 的指定日历（如"麦麦活动"）添加事件与提醒。优点：无需额外依赖，事件立即出现在所有已登录 iCloud 的设备上。
- **方案 B（兜底）：生成 `.ics` 文件**。用户双击导入，兼容无自动化权限的场景。

### 3.2 去重策略

`campaign-calendar` 返回为 Markdown 文本、无活动唯一 ID，因此以 `SHA1(活动标题 + 所属日期)` 作为事件的 UID 写入日历，同步前先查询目标日历已有 UID 集合，跳过已存在事件，保证重复执行不产生冗余。

### 3.3 提醒策略

默认在活动开始前 1 天触发 VALARM 弹窗提醒；支持用户自定义（如提前 1 小时）。

### 3.4 数据降级

`campaign-calendar` 实测返回 **Markdown 文本**（按日期分组：`#### yyyy年M月d日` + 活动标题/内容介绍/图片），解析层策略：

- 日期：以分组头日期为准（活动当天，全天事件）；若内容介绍中可正则提取到明确开售日期（如"10月8日 10:30起开售"），优先使用该日期；
- 标题：取 `**活动标题**：` 行；内容介绍与图片 URL 拼入事件备注；
- 去除 Markdown 图片标签，保留纯文本描述；
- 解析失败的条目跳过并记录日志，不中断整体同步。
